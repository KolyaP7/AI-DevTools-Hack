# Исправление ошибки "All connection attempts failed"

## Проблема

Ошибка `All connection attempts failed` при вызове `get_text_from_video` возникает из-за несоответствия транспортных протоколов между MCP сервером и LLM системой.

### Причины ошибки:

1. **LLM система** (файл `LLM/gigachat_llm.py`) пытается подключиться к MCP серверу через HTTP:
   ```python
   MCP_BASE_URL = "http://localhost:8000/mcp"
   ```

2. **MCP сервер** по умолчанию запускается в режиме `stdio`, а не HTTP:
   ```python
   mcp.run(transport="stdio")  # Режим по умолчанию
   ```

3. HTTP режим включается только при явном указании параметра `--http` или переменной окружения `MCP_TRANSPORT=http`.

## Решение

### 1. Автоматическое включение HTTP режима

Изменен файл `mcp/server.py` для автоматического включения HTTP транспорта, если не отключено явно:

```python
use_http = "--http" in sys.argv or os.getenv("MCP_TRANSPORT") == "http"

# Включаем HTTP транспорт по умолчанию для поддержки LLM системы
if not use_http and os.getenv("ENABLE_HTTP_FOR_LLM", "true").lower() != "false":
    use_http = True
```

### 2. Улучшенная обработка ошибок в LLM системе

Изменен файл `LLM/gigachat_llm.py` для лучшей диагностики проблем соединения:

- Добавлена проверка доступности MCP сервера
- Улучшена обработка ошибок соединения
- Добавлена диагностика причин сбоев

## Способы запуска

### Вариант 1: Автоматический HTTP режим (по умолчанию)

```bash
python run_server.py
```

HTTP режим включится автоматически для поддержки LLM системы.

### Вариант 2: Явное указание HTTP режима

```bash
python run_server.py --http
```

### Вариант 3: Отключение HTTP режима (для разработки)

```bash
export ENABLE_HTTP_FOR_LLM=false
python run_server.py
```

### Вариант 4: Режим разработки (stdio)

```bash
export MCP_TRANSPORT=stdio
python run_server.py
```

## Проверка работы

1. Запустите сервер: `python run_server.py`
2. Убедитесь, что в выводе есть:
   ```
   🌐 ЗАПУСК MCP СЕРВЕРА
   🚀 MCP Server: http://localhost:8000/mcp
   ```
3. Запустите тест системы: `python test_system.py`

## Диагностика проблем

Если ошибка повторяется:

1. **Проверьте порт**: Убедитесь, что порт 8000 не занят другим процессом
2. **Проверьте брандмауэр**: Убедитесь, что локальные подключения к порту 8000 разрешены
3. **Проверьте переменные окружения**: Убедитесь, что нет конфликтующих настроек транспорта
4. **Проверьте логи**: Смотрите подробные сообщения об ошибках в консоли

## Альтернативные решения

Если HTTP режим не подходит, можно изменить LLM систему для работы через stdio, но это потребует значительных изменений в архитектуре.
